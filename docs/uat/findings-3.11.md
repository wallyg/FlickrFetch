# UAT 3.11 findings (collected, not fixed yet)

Rule: collect all UAT feedback first, fix in one pass, build once.

1. **FIXED in the fix pass, check with F5 and F6.** **Many album chips wrap clumsily (25 Nov, owner, On This Day with ten albums picked).** The chips sit in the same row as the privacy and Photos / Videos controls, wrap onto two more lines and push the hint line and the Photo size slider around. Fix idea: chips in their own row below the controls, as the Map does, with a "Clear all" link.

2. **FIXED in the fix pass, check with F4 (owner confirmed this reading).** **Picking an album shows no response where you are looking (25 Nov, owner).** "There was no response in the window you're in, just a refresh behind it." Likely reading: the suggestion list stays open over the area where the new chip appears (the chips wrap onto the rows below the box), so the click seems to do nothing while the counts change behind it. To confirm with the owner. Fix idea: albums already picked stay in the list with a tick (so the click answers on the spot), and the chips sit in their own row that the list does not cover.

3. **FIXED in the fix pass, check with F3 (decision: six levels everywhere).** **Privacy choices differ between the tabs (25 Nov, owner).** Photostream and the Map use six choices (All, Public, Friends, Family, Friends & Family, Private) inside the Filters drawer; On This Day and the Timeline use three (All, Public, Not public) in the main row, with a count in each button. Different words, different places, counts in only one. Photostream cannot do "Not public" (Flickr's search takes one level at a time). Decision needed, see below.

4. **FIXED in the fix pass, check with F6.** **Clear all (25 Nov, owner, answering the UAT question): yes.** On This Day and the Timeline get a "Clear all" for every filter at once, as the Map has.

Proposed direction for 1 to 4 together (waiting for the owner): one filter pattern on all four tabs. All / Photos / Videos stays in the main row; a Filters button (with a count badge) opens a drawer with Privacy, Album (and Tags where the tab has them); picked filters show as chips in their own row with Clear all. This is how the Map and Photostream already work.

Fix pass (25 Nov): the privacy level joined the shared filter in `dateViews.ts` (`DateExtra.privacy`, exact level, ignored before a Rebuild), with a count per level (`levels`) for the drawer; `DateFilterBar` is now the Map-style pattern (media switch in the row, Filters drawer with the six privacy choices and the album box, chips in their own row with Clear all); `AlbumBox` shows picked albums ticked in its list and toggles them; "Open in Photostream" carries Photos / Videos and one privacy level (the owner does not use it; kept, with an honest tooltip for albums, which Flickr's search cannot filter by). Tests 151 (14 for the date filters; 14 break-checks caught).

5. **FIXED, check with G4b. "Show on the map" only appears on one location check (25 Nov, owner, testing G3; the owner said everything else in the batch looks good).** It shows for "Far from the place its title names" and (only when the photos around it agree on a place) for a photo with no location, but not on the other location checks. Cause: the button only exists where the app already works out a place to show (`hintGeo`); the other checks have a place (the photo's own geotag) but nothing hands it to the button. Fix idea: give every location check with a geotag the button, using the photo's own geotag: Vague location, Far from its neighbours, and Location at 0, 0 (which shows the ocean at 0, 0). "No location" keeps it only where a suggestion exists, since there is no place to show otherwise. Needs a restart of the dev app to test, because it is background code. Waiting for the owner to confirm which checks.

Fix (25 Nov): `ownPlace()` in `photoHealth.ts` gives rows of Vague location, Far from neighbours and Location at 0, 0 their own geotag as `hintGeo`; a photo with no geotag has none. Tests 161 (3 new, 4 break-checks caught).
