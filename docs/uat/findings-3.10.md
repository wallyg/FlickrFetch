# UAT 3.10 findings (collected, not fixed yet)

Rule: collect all UAT feedback first, fix in one pass, build once.

1. **FIXED in the fix pass, check with M23. The world does not wrap (24 Nov, owner, while testing).** Zoomed out, you cannot scroll left or right across the edge of the map: the map stops at 180 degrees and the world is drawn once, so there is empty space beside it (zoom 1 is 512 px wide, narrower than the window) and you cannot pan across the date line to see Fiji or the Aleutians continue on the other side. Likely cause: longitude is clamped to -180..180 (`MapPanel.tsx`, `zoomTo`, `onMove`, `onKey`) and the outline, tiles and dots are drawn once. Fix idea: let the centre run past the edge, draw the outline, street tiles and dots in repeated copies of the world (-1, 0, +1 and as many as the window shows), turn the longitude back into -180..180 when asking for dots (the server already handles a window that crosses the date line), and make clicking a dot work on any copy. A photo then appears once per copy, which is the normal behaviour of a flat world map.

Fix pass 24 Nov: `shared/mapGeo.ts` gained `wrapLon` and `worldCopies` and `visibleTiles` now wraps columns; `MapPanel.tsx` draws the outline and dots once per visible copy of the world, wraps the centre instead of clamping it, asks for dots with wrapped west and east (the server already treats west greater than east as crossing the date line), and hit-tests every copy. Tests 122 (new ones mutation-checked five ways). No other feedback was reported.

2. **FIXED in the fix pass, check with M24. The map does not scroll vertically (24 Nov, owner, while testing). Gesture confirmed: two-finger scroll.** Likely cause: the mouse wheel and trackpad two-finger scroll are both turned into zoom only (`MapPanel.tsx`, the `wheel` handler uses `deltaY` for zoom and ignores `deltaX`), so a two-finger swipe up or down zooms instead of moving the map, and a sideways swipe does nothing. This may also have been behind finding 1 ("cannot scroll left or right"), on top of the missing wrap. Dragging with the pointer moves both ways in the code. Fix idea (the way most trackpad-friendly maps work): two-finger scroll pans in any direction, pinch zooms, Cmd + scroll zooms, and a physical mouse wheel zooms (told apart by its big whole-number steps). Pure function `wheelIntent` with tests.

3. **FIXED in the fix pass, check with M25. Stuck in a view with empty space above the map (24 Nov, owner, screenshot with the street map on).** The view shows the top of the world at the bottom of the window and a plain blue band above it where there is no map (north of the pole), with the street map on. Likely cause: only the middle of the view is kept between 85 degrees north and south, so the map can be dragged until half the window shows nothing, and at the lowest zooms the whole world is shorter than the window so blank bands show above and below. Combined with finding 2 (two-finger scroll zooms instead of moving the map) it feels stuck. Fix idea: keep the window inside the map vertically (the view stops at the poles, and is centred if the world is shorter than the window), and set the lowest zoom from the window height so the world always fills it top to bottom. The world already repeats sideways, so only up and down need limits. Tests for the limit function. Workaround now: drag with the pointer pressed, or use the + and - buttons.

4. **FIXED in the fix pass, check with M26. The map's size is not responsive (24 Nov, owner).** With no photo tray the map was short and very wide; opening the tray made it much taller; closing the tray kept that height and only widened it. Cause (two parts): the Map tab's wrapper used `flex: 1` inside a pane that is not a flex box, so it was only as tall as its content (about 300 px, or as tall as the photo tray's thumbnails), and the canvas held the box's height open (the canvas height came from the box, and the box height came from the canvas), so it could grow but never shrink. Fix: the wrapper is `height: 100%`, and the canvas is positioned absolutely so only the window decides the size. This also made finding 3 worse than it looked (a very tall box means a very tall blank band), and it matters for the new lowest-zoom rule, which uses the box height.

Fix pass 2 (24 Nov), findings 2 to 4: `shared/mapGeo.ts` gained `wheelIntent`, `limitCentre`, `minZoomFor`; `MapPanel.tsx` pans on two-finger scroll, zooms on pinch, Cmd + scroll and notched wheels, keeps the view between the poles, raises the lowest zoom to the world's height, and fills its tab. Tests 126 (new ones mutation-checked seven ways).

5. **FIXED in the fix pass, check with M27. The map does not keep its place when the box resizes (24 Nov, owner).** The view kept the point at the middle of the box fixed, so when the photo tray opened and the box narrowed the whole picture slid left (and what was just clicked could end up under the tray); closing the tray slid it back the other way. Fix: `anchorAfterResize` in `shared/mapGeo.ts` keeps the top left corner of the map where it is (new room appears at the right and bottom), and keeps a picked circle that was in view at least 40 px from every edge. A circle that was already out of view does not pull the view back. `MapPanel.tsx` calls it from the resize watcher, in the same update as the new size so there is no flash. Tests 133 (the new ones mutation-checked nine ways). Alternative if you prefer it: keep the middle of the view fixed instead of the top left.
